# 2026-11-23 四项接入开发与验证计划

## 范围

依据《vLLM-Ascend与上游Inductor接入差距及TorchNPU新特性价值评估》的推荐顺序，本轮四项工作定义为：

1. 缓存身份与正确性：恢复 `TeSourcePinPass`，验证 TE 指纹和新增编译配置进入相应缓存键。
2. 普通 AOT：在未修改基线上验证 Qwen3-0.6B 的跨进程保存、强制加载、输出一致性和温启动收益；standalone 与 Mega AOT 不在未证明普通 AOT 价值前扩展。
3. 性能定位：先复测 DeepSeek-V2-Lite BF16 的 default/Inductor decode；仅当当前 A5 仍存在可区分回退时采集 device timeline，并只处理绝对耗时最大的前一至两项。
4. 通用基础设施：增加类型化 TE 配置传递，处理 spawn、缓存键和实例隔离；为 `cpp_wrapper=True` 推导 `triton.autotune_at_compile_time=True` 并验证非捕获及 ACLGraph 路径。

## 环境与约束

- 容器：`inductor_feature_z00896543_20261122_140509`。
- 起始 vllm-ascend 提交：`50f44f0952970d97b1701fc3f8288b6a88b27ac0`，工作区干净。
- 所有 Python 测试先 `source env.sh`；需要判定通过的测试使用清缓存流程或本轮独立缓存根。
- 每次启动 NPU 测试前重新执行 `npu-smi info`，只选当时无进程的卡。
- 首次检查中 2、3、4、5、7 号卡无进程；随后 2 号卡出现其他任务，因此实际 AOT 测试改用再次确认空闲的 3 号卡。0/1/6 号卡已有任务，不使用。

## 验收证据

- 代码改动与对应单元测试；真实模型验证保存原始日志、JSON、环境及缓存证据。
- AOT 冷/暖启动必须是两个新操作系统进程；第二次设置 `VLLM_FORCE_AOT_LOAD=1`，禁止加载失败后静默重编。
- 性能结论以非 profiling 的端到端数据为准，timeline 只用于定位。
- 所有本轮文档使用 `YYYYMMDD_HHMMSS_` 前缀；patch 归档到本目录 `Patch/` 下对应特性目录，patch 文件同样带时间前缀。
