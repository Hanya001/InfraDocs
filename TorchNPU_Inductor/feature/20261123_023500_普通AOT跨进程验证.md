# 2026-11-23 普通 AOT 跨进程验证

## 配置与判据

模型为 `/mnt/weight/Qwen/Qwen3-0.6B`，BF16，`backend=inductor`，默认 `FULL_AND_PIECEWISE`，spawn worker。AOT 与 FX 对照分别使用独立缓存根；冷启动均清缓存，温启动保留各自完整缓存。

AOT 第二次及后续启动设置 `VLLM_FORCE_AOT_LOAD=1`，防止加载失败后静默重编。standalone 和 Mega AOT 均保持关闭。每次启动前重新检查 `npu-smi info`，本组使用当时空闲的 3 号卡。

## 功能结果

- 初次基线冷启动成功保存 AOT `model`，完成真实生成和 ACLGraph replay。
- 新进程出现 `Directly load AOT compilation from path .../rank_0_0/model` 与 `Directly load the compiled graph(s) ... from the cache`，没有重编回退。
- 两个固定请求各生成 48 tokens，冷/暖 token IDs 逐项一致。
- 最终代码重新保存的 AOT 产物路径哈希为 `ed90e809...`；强制温加载使用外层 FX 目录 `7ea1374c2d/backbone`，输出仍一致。
- 新增配置字段改变 AOT 配置哈希后，对旧路径强制加载会明确报 `FileNotFoundError`，没有静默使用不匹配产物；随后以最终配置重新保存并加载成功。

## 最终代码重复温启动

为避免旧配置哈希干扰，普通 FX 使用新的独立缓存根完成一次冷启动，再与 AOT 一样测量 3 个新进程。AOT 每次都设置 `VLLM_FORCE_AOT_LOAD=1`。

| 指标 | 普通 FX 三次 | 普通 AOT 三次 | 中位数差异 |
|---|---|---|---|
| `LLM` 构造 | 71.567、71.429、71.467 s | 68.596、75.245、68.692 s | AOT 中位数 68.692 vs 71.467 s，减少 2.775 s（3.88%） |
| 进程 wall time | 87.519、87.316、87.407 s | 84.540、90.959、84.546 s | AOT 中位数 84.546 vs 87.407 s，减少 2.861 s（3.27%） |
| 日志中 compile/load | 5.90、5.98、5.86 s | 2.88、4.62、2.87 s | 中位数减少 3.02 s |

AOT 第二次受到系统波动影响，但三次均强制加载成功、没有重编回退，所有冷/暖及 FX/AOT 请求 token IDs 一致。收益主要体现在跳过 Dynamo tracing，属于当前小模型上约 3 秒的有限但可重复收益；不能外推到更大模型或所有部署形态。

普通 AOT 已满足本轮可行性验收。standalone 需要继续处理 NPUBIN/Triton 打包恢复、动态 shape 和多个子图，本轮没有直接放开其显式报错；Mega AOT 也未开启。

## 已知噪声与边界

- 两种路径首次请求仍出现请求期 Triton JIT 警告，AOT 不覆盖这些辅助 kernel，也不缓存 ACLGraph capture。
- 冷启动耗时约 480 秒，其中初次 profiling/warmup 占比较大；温启动收益不能直接外推为冷启动收益。
- 本项只验证普通 AOT。是否继续 standalone 需在重复温启动确认额外收益后决定；Mega AOT 不在本轮直接开启。
