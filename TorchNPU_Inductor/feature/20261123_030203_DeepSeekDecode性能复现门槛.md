# 2026-11-23 DeepSeek decode 性能复现门槛

## 目的

评估文档建议只有定位到当前环境中的实际回退后，才投入 `FixFunctionalizationPass`、通用 NPU FX pass 或具体 kernel 修改。本轮先复现 DeepSeek-V2-Lite BF16 的历史 decode 短板，不预设需要优化。

## 方法

- 模型：`/mnt/weight/DeepSeek-V2-Lite`，BF16，TP1。
- 固定负载：输入 128 tokens、输出 512 tokens、batch 1，greedy，关闭 prefix cache。
- 两侧均为 `FULL_AND_PIECEWISE`，capture sizes `[1, 2, 4, 8, 16, 24, 32]`，V2 model runner。
- default 与 Inductor 分别使用独立缓存，warmup 1 次、正式测量 3 次，按中位数比较。
- 每次启动前重新检查 NPU；两组均使用当时无进程的 3 号卡。

## 结果

| 指标 | default | Inductor | Inductor / default |
|---|---:|---:|---:|
| 输出吞吐中位数 | 232.0 tok/s | 232.6 tok/s | 1.003× |
| 请求 wall 中位数 | 2.207 s | 2.201 s | 0.997× |
| TPOT 中位数（JSON 保留精度） | 0.0042 s | 0.0042 s | 持平 |
| TTFT 中位数 | 0.0516 s | 0.0453 s | 降低 12.2% |

逐次吞吐：default 为 232.0、227.4、237.4 tok/s；Inductor 为 236.6、232.6、228.2 tok/s。两侧区间高度重叠，未复现历史 910B3 上约 7% 的 decode 回退；这也与 2026-11-22 A5 矩阵中六组性能均通过的结果一致。

## 决定

按预先设定的停止条件，本轮不采集 device timeline，也不新增性能 patch。当前 A5 负载没有需要由 timeline 解释的可区分回退，继续做 kernel 或 copy 优化会缺乏目标证据。

本结论仅覆盖上述模型、负载和当前软件栈，不否定其他模型或 shape 的性能问题，也不处理该模型已单独记录的 logprob/重复异常正确性问题。

原始日志、逐次 JSON 和脚本快照位于 `server-results/inductor-feature/20261123_gap/decode_perf/`。准备好的 profiling 脚本保留在 `server-scripts/a5/20261123_inductor_gap/`，未用于生成性能结论。
