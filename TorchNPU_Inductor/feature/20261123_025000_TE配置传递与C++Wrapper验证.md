# 2026-11-23 TE 配置传递与 C++ Wrapper 验证

## 实现

- `ascend_compilation_config.triton_experimental_config` 新增类型化字典，默认 `{}`。非空时按当前 TE `get_type()` 逐项校验和规范化，支持点号子配置；未知键和错误类型直接报错。
- worker 侧包装 `InductorAdaptor.compute_hash()`，把当前引擎配置复制到 adaptor 实例；`compile()` 全程在 `te_config.patch()` 中执行，正常返回和异常均恢复。没有新增环境变量。
- 配置身份复用现有 `VllmConfig.compute_hash()` 与 TE backend config 的 FX 缓存机制，没有另造哈希。
- `inductor_compile_config.cpp_wrapper=True` 时，以 `setdefault` 推导 `triton.autotune_at_compile_time=True`；显式 False 不覆盖。
- additional config 用户文档和 patch 生命周期说明已同步更新。

新增 patch 的 Ruff 检查和格式检查通过，`git diff --check` 通过。全仓 `format.sh ci` 仍受已有 Ruff/codespell 问题、缺少 shellcheck 和 gitleaks 架构不匹配影响；自动格式化产生的非目标文件改动已全部还原，本轮不将这些既有问题算作新特性失败。

## 真实模型：通用 TE 配置

Qwen3-0.6B、spawn、`cudagraph_mode=NONE`、冷缓存，传入：

```json
{"vf_fusion_mode": "max-parallel"}
```

引擎正常生成。多份真实生成的 Inductor Python 产物均包含：

```text
'npu_backend_config': {..., 'vf_fusion_mode': 'max-parallel', ...}
```

这证明配置穿过 additional config、spawn worker 和逐次 `config.patch` 进入实际 TE kernel 编译，而不是只停留在配置对象。输出 token 已保存。

## 真实模型：C++ wrapper 非捕获路径

Qwen3-0.6B、spawn、`cudagraph_mode=NONE`、未显式传 autotune 配置：

- 生效配置同时包含 `cpp_wrapper=True` 和自动推导的 `triton.autotune_at_compile_time=True`。
- 冷缓存编译及生成通过，没有 TE lazy compilation 的 `NotImplementedError`；`init_s=219.713 s`。
- 新进程温缓存直接加载编译图并生成通过，`init_s=70.431 s`；冷/暖 token IDs 一致。

## 真实模型：C++ wrapper 与 ACLGraph

在相同模型和 spawn 配置下改用 `FULL_AND_PIECEWISE`，冷缓存编译、capture 和真实生成均通过；日志包含 `Graph capturing finished` 和 `ACL graph replay is active`。最终配置仍包含自动推导的 autotune 项，输出与非捕获路径一致，`init_s=210.524 s`。

以上只证明功能组合可用。ACLGraph 重放不会逐 kernel 经过 Python/C++ wrapper，本轮没有据此宣称已捕获 decode 的稳态性能收益。
