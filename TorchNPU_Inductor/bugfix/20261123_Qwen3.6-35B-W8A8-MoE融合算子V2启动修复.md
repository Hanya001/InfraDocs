# Qwen3.6-35B-A3B-W8A8：旧 NZ 融合算子缺动态 shape 配置导致启动失败

## 1. 结论

- 问题环境：A5-25 `inductor_214build_z00896543_20261120_1546`，Ascend950DT、CANN 9.2.0、torch/torch_npu 2.13、vLLM/vLLM-Ascend 0.33，TP2。
- 影响模型：`/mnt/weight/Qwen3.6-35B-A3B-w8a8`，W8A8 Dynamic MoE。
- eager、default 和 Inductor 共用的 MoE 融合算子在初始化 profiling 阶段失败，不是 Inductor 独有缺陷。
- 修复方式：普通 W8A8 融合分支从旧 `grouped_matmul_swiglu_quant_weight_nz` 切换到当前 CANN 已有动态 shape 配置的 `npu_grouped_matmul_swiglu_quant_v2`，保留融合计算。
- 修复提交：vLLM-Ascend `7db008b78864095119a6552376af65a29b2c9463`，分支 `rebase/community-main-20261119`。
- 当前环境启动问题已修复；该结论不外推为所有模型、所有 CANN 版本或所有 SwiGLU 变体均已验证。

## 2. 现象与直接证据

35B eager 任务集和固定输入测试最初都在初始化阶段失败。早期外层日志只有 `WorkerProc hit an exception`，随后直接运行 eager 才得到底层错误：

```text
call aclnnGroupedMatmulSwigluQuantWeightNZ failed
Config_Error(EZ1013)
In the dynamic shape scenario, the JSON configuration file of operator
aclnnGroupedMatmulSwigluQuantWeightNZ_1692_GroupedMatmulSwigluQuant
cannot be found.
```

失败发生在 Worker 的初始显存 profiling 阶段，尚未进入正常请求推理。因此，外层的 Worker 退出和测试进程清理都是后续现象，不是独立根因。

## 3. 调用链与根因

相关调用链为：

```text
W8A8 Dynamic MoE
  → AscendW8A8DynamicFusedMoEMethod.apply_gmm1_act_quant
  → 普通融合分支（fusion=True，且不是 SWIGLUOAI_UNINTERLEAVE）
  → grouped_matmul_swiglu_quant_weight_nz
  → CANN 动态 shape 配置缺失
```

旧接口在当前 CANN 安装中缺少动态 shape 配置，而 `GroupedMatmulSwigluQuantV2` 已有对应配置。问题属于 vLLM-Ascend 对当前 CANN 可用接口的适配，不需要通过关闭融合来规避。

## 4. 修复内容

文件：`vllm_ascend/quantization/methods/w8a8/w8a8_dynamic.py`。

原调用：

```python
hidden_states, swiglu_out_scale, _ = torch.ops._C_ascend.grouped_matmul_swiglu_quant_weight_nz(
    x=hidden_states,
    weight=w1[0],
    weight_scale=w1_scale[0],
    x_scale=pertoken_scale,
    bias=None,
    swiglu_limit=mlp_compute_input.swiglu_limit,
)
```

修复后：

```python
hidden_states, swiglu_out_scale = torch_npu.npu_grouped_matmul_swiglu_quant_v2(
    x=hidden_states,
    weight=w1,
    group_list=cumsum_group_list(
        mlp_compute_input.group_list,
        mlp_compute_input.group_list_type,
        0,
    ),
    weight_scale=w1_scale,
    x_scale=pertoken_scale,
    bias=None,
)
```

具体变化：

1. 改用当前环境可用的 V2 融合算子；
2. 权重和 scale 按 V2 schema 传列表，不再解包成单个 `Parameter`；
3. 按 V2 签名接收两个返回值；
4. 删除 V2 不支持的 `swiglu_limit`；当前模型走普通 SwiGLU，本路径不依赖该参数。

## 5. 必要性与影响边界

### 对当前 35B-W8A8 是必要的

旧接口在当前环境稳定阻塞启动。要恢复运行，需要切换可用接口、补充 CANN 旧接口配置，或更换运行环境。本次选择只修改 vLLM-Ascend，不修改 CANN 或 Triton-Ascend。

### 不影响其他路径

修改只进入 W8A8 Dynamic MoE 的普通融合分支。BF16、非 MoE、其他量化格式、EPLB 专用分支、`SWIGLUOAI_UNINTERLEAVE` 和非融合分支均不使用此修改。

### 精度和性能结论边界

- eager 和 Inductor 共用修改后的 V2 调用，因此不存在一条路径使用旧 NZ、另一条使用 V2 的差异。
- 两个接口的目标语义相同，但底层 kernel 和布局实现不同，仍需真实模型数值验证。
- 旧接口在当前环境无法完成运行，不能据此构造旧接口与 V2 的有效性能对比。
- 修复后的 default/Inductor 两轮性能比较均满足既定阈值，但这不等于证明 V2 相对旧接口无性能变化。
- 当前 35B 固定输入 logprob 比较仍超过容差；不能把启动修复等同于完整精度验收通过。
