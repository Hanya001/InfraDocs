# FFN 的计算

FFN 又叫 **Position-wise Feed-Forward Network**，更直观地翻译就是“逐 token 独立处理的前馈网络”。

对于每个 token 的隐藏向量使用**同一套 FFN 权重**，各自独立计算，不会在 FFN 内部互相交换信息。

因此，Decode 第 `t` 步时：

```
历史 token 1 ──► 提供缓存的 K/V ──┐
历史 token 2 ──► 提供缓存的 K/V ──┤
       ...                     ├──► 当前 token 的 Attention ──► 当前 token 的 FFN
当前 token t ──► 当前 Query ────┘
```

当前这一层的 FFN 只需要处理当前 token 经 Attention 后的隐藏向量：[B, 1, D]， 原因有两个：

1. **FFN 本身不看历史**：当前 token 的 FFN 结果只由当前隐藏向量和固定权重决定。
2. **因果 Attention 下历史结果不会变化**：历史 token 不会关注未来 token，它们以前计算出的各层结果仍然有效；后续 Attention 所需的历史信息已经以 **K/V Cache** 的形式保存。

这里不同Batch之间也是相互不影响的，所以可以放在一起直接并行。**这正是可以把多个请求组成 Batch 并行计算的根本原因。**以 Decode 阶段的 FFN 为例：

```
请求 A：xA [1, D] ──┐
请求 B：xB [1, D] ──┼──► X [B, D] ──► FFN ──► Y [B, D]
请求 C：xC [1, D] ──┘                       │
                                            ├─► yA：只由 xA 计算得到
                                            ├─► yB：只由 xB 计算得到
                                            └─► yC：只由 xC 计算得到
```

从矩阵乘角度看，`X [B,D] @ W1 [D,I]` 的第 `b` 行只使用 `X` 的第 `b` 行，不会把不同请求的行相加或混合。
