# Qwen3.5-35B-A3B-w8a8-mtp 历史脚本复现记录

日期：2026-11-26

## 结论

在当前 950DT 环境和现有代码上，使用历史 `bench_inductor_perf.py` 及相同的固定负载配置，**没有复现历史报告中的 batch32 加速 14% 和 prefill 加速 7%**。

- batch32：历史加速比 1.143，本次为 **0.999**。
- prefill：历史加速比 1.068，本次为 **0.976**。
- 开启 1-token MTP 后，S3fp 相对 S2 的加速比为 **1.014–1.049**；MTP 本身相对关闭时的吞吐提升为 S2 **1.115–1.354×**、S3fp **1.159–1.384×**。
- 本次已对齐历史脚本、负载、图模式、捕获档位和 MTP 配置。剩余主要变量是 **910B3 与 950DT 的硬件差异，以及两个时间点的代码差异**，目前不能归因到某个具体 kernel。

本文只记录这次历史脚本复现，不包含在线服务性能和固定 token 精度结果。

## 1. 历史结果与复现目的

历史报告：`inductor-meta-worktree/docs/vllm/vllm_ascend_inductor_design/stage design/stage6/RESULTS.md`

其中 Qwen3.5-35B-A3B-w8a8-mtp 的主要结果为：

- decode 加速比 1.00；
- batch8 加速比 1.06；
- batch32 加速比 1.14；
- prefill 加速比 1.07。

后续在线服务测试得到不同的加速比，因此需要用历史脚本和固定负载重新检查，排除测试入口、请求到达方式和输入输出长度差异。

## 2. MTP 配置说明

权重目录名中的 `mtp` 只表示 checkpoint 包含 MTP 相关权重，不表示运行时自动启用 MTP 投机解码。运行时需要通过 `speculative_config` 显式启用。

历史主矩阵的 S2 和 S3fp 结果均未传入 `speculative_config`。历史脚本另有单独启用 MTP 的补充测试，但不属于产生上述 batch32 和 prefill 加速比的主矩阵。

本次复现同样未传入 `speculative_config`，因此与历史主矩阵一致，**两条路径均为 MTP 关闭**。MTP 不是本次结果差异的来源。

## 3. 测试方法

使用历史脚本：

`inductor-meta-worktree/docs/vllm/env/scripts/bench_inductor_perf.py`

实际执行两条命令：

```bash
python bench_inductor_perf.py --model q35a3mtp --scenario s2 --tp 2 --reps 3
python bench_inductor_perf.py --model q35a3mtp --scenario s3fp --tp 2 --reps 3
```

测试方式与历史主矩阵一致：

- 离线 `LLM.generate`，不经过在线 HTTP 服务；
- 每种负载执行 1 次预热和 3 次正式重复；
- 汇总正式重复的中位数，不把预热计入结果；
- 两条路径使用相同输入 token、输出长度和 batch；
- S2 使用 default 路径，S3fp 使用 Inductor 路径；
- `cudagraph_mode=FULL_AND_PIECEWISE`；
- `custom_ops=['all']`；
- 捕获档位均为 `[1,2,4,8,16,24,32]`；
- `weight_nz_mode=0`，量化方式为 `ascend`；
- 两条路径使用独立缓存。

固定负载如下：

| 名称 | 输入长度 | 输出长度 | batch |
|---|---:|---:|---:|
| w1_decode | 128 | 512 | 1 |
| w4_b1 | 1024 | 256 | 1 |
| w4_b8 | 1024 | 256 | 8 |
| w2_b32 | 1024 | 256 | 32 |
| w3_prefill | 4096 | 128 | 8 |

## 5. AOT cache 问题处理

首次有效尝试在引擎初始化阶段报错并长时间未退出：

```text
AssertionError: expected OutputCode, got GraphModuleImpl
```

错误发生在 `AOTAutogradCache.make_entry`。清理该任务的进程后，设置：

```bash
export TORCHINDUCTOR_AUTOGRAD_CACHE=0
```

并使用全新结果目录和独立缓存重新运行。最终 S2 和 S3fp 均正常完成，以下数据全部来自这次成功运行。每条路径另设置 1 小时超时保护，避免失败后一直等待。

## 7. 分析

这次复现与历史主矩阵使用相同的脚本和固定负载，因此不能再把差异解释为在线 HTTP 服务、QPS 到达方式或变长请求造成的。两条路径也都没有启用 MTP。

当前可以确认的现象是：

- decode 和 batch1 的吞吐基本持平；
- batch8 本次略有下降，历史为上升；
- batch32 从历史约 14% 的提升变为基本持平；
- prefill 从历史约 7% 的提升变为约 2.4% 的下降。

尚未进一步确定具体原因。下一步如需定位，应在相同 950DT 环境下对历史代码与当前代码运行同一脚本，并保存 Inductor 编译产物和 kernel 级 profiling，区分代码变化与硬件 kernel 表现变化。

## 9. 开启 1-token MTP 的历史脚本对照

### 9.1 配置说明

在用户提供的选择下，本次使用与历史补充脚本一致的配置：

```json
{"method":"mtp","num_speculative_tokens":1}
```

`num_speculative_tokens=1` 表示每轮生成 1 个候选 token，与模型配置中的 `mtp_num_hidden_layers=1` 不是同一个概念。当前 Qwen3.5/3.6 的官方 950DT 示例使用 `qwen3_5_mtp` 和 3 个候选 token，因此本文结果应理解为 **1-token MTP 配置下的测量结果，不代表官方推荐的 3-token 配置**。

仍使用历史 `bench_inductor_perf.py` 主程序，只在调用层给 S2 和 S3fp 加入上述 `speculative_config`。其余负载、预热、3 次正式重复、TP2、NPU 2、3、独立缓存和 `TORCHINDUCTOR_AUTOGRAD_CACHE=0` 均与前述复现一致。两份结果 JSON 均确认存在该 MTP 配置，运行日志也包含 SpecDecoding 接受率统计。

开启 MTP 后，两条路径的捕获档位都变为 `[1,2,4,8,16,24,32,40,48,56,64]`。S2 初始化 231.4 秒，S3fp 初始化 287.2 秒，最终输出 `REPRO_MTP_COMPLETE`。

### 9.2 结果

“Inductor/default”表示 S3fp 相对 S2 的加速比；“S2 MTP 收益”和“S3fp MTP 收益”分别表示同一路径开启 MTP 后相对关闭时的吞吐提升。

| 负载 | 关闭时 Inductor/default | 开启后 S2 tokens/s | 开启后 S3fp tokens/s | 开启后 Inductor/default | S2 MTP 收益 | S3fp MTP 收益 |
|---|---:|---:|---:|---:|---:|---:|
| decode 128/512/b1 | 1.002 | 174.7 | 178.9 | 1.024 | 1.354 | 1.384 |
| 1024/256/b1 | 1.004 | 165.9 | 171.8 | 1.036 | 1.324 | 1.366 |
| 1024/256/b8 | 0.991 | 888.1 | 931.4 | 1.049 | 1.202 | 1.271 |
| 1024/256/b32 | 0.999 | 2287.9 | 2333.5 | 1.020 | 1.176 | 1.201 |
| prefill 4096/128/b8 | 0.976 | 564.4 | 572.2 | 1.014 | 1.115 | 1.159 |

### 9.3 结论

- 开启 1-token MTP 后，Inductor 相对 default 的加速比为 **1.014–1.049**，五种负载均为正收益。
- batch32 的 Inductor/default 加速比从关闭时的 0.999 变为 **1.020**，但仍低于历史未开 MTP 时的 1.143。
- prefill 的 Inductor/default 加速比从关闭时的 0.976 变为 **1.014**，从历史对比角度仍未复现 1.068。
- MTP 本身对两条路径都有明显收益：S2 提升 **1.115–1.354×**，S3fp 提升 **1.159–1.384×**。因此“Inductor 相对 default 的加速比”和“开启 MTP 带来的加速比”必须分开解读。
