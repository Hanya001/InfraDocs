## 2. 测试方法

### 2.1 三路径

生成模型依次运行：

- `eager`：`enforce_eager=True`。
- `default`：当前生产默认编译路径。
- `inductor`：`compilation_config.backend="inductor"`。

三条路径使用同一权重、输入和运行参数：BF16 引擎 dtype、`max_model_len=8192`、`max_num_seqs=32`、`gpu_memory_utilization=0.80`、seed 0、关闭 prefix cache。小模型使用 TP1，27B/35B 等双卡模型使用 TP2。

### 2.2 正确性

- 使用 12 条中英文提示词，greedy、最多 128 tokens，每条路径重复生成 2 轮。
- 同时比较完整 token ID 序列和 tokenizer 解码后的最终文本，没有再对文本做二次 tokenize。
- token 不一致不阻塞性能测试；只有报错、空输出或明显乱码才停止。
- 这里的 12 条输出比较不是标准精度测试集。所有非全一致项仍需后续标准测试集综合评估，不能据非空生成判定精度通过。
- Embedding 模型使用 8 条不同长度输入，比较 1024 维向量的最大绝对误差和余弦相似度。

### 2.3 性能

沿用 bench213 负载：8 条串行短请求、16 路并发短请求、4 条较长输入；预热后正式测量 3 次取中位数。记录单请求及 16 路吞吐、TTFT、解码速度、长输入 TTFT 和引擎初始化时间。

该负载不同于覆盖矩阵规定的完整五组 ISL/OSL/batch 性能负载，因此本文不能替代完整 Release 性能验收。

## 7. 失败和阻塞原因

### 7.1 eager 基线阻塞

以下三个 W8A8 MoE 模型均在 eager 初始化阶段失败，未运行 Inductor，不能记为 Inductor 通过或失败：

- DeepSeek-V2-Lite-W8A8。
- Qwen3-30B-A3B-W8A8。
- Qwen3.6-35B-A3B-w8a8。

共同根因：

```text
npu_grouped_matmul_swiglu_quant_v2()
Expected a value of type 'List[Tensor]' for argument 'weight'
but instead found type 'Parameter'
```

### 7.2 Inductor 初始化失败

- Qwen2.5-VL-7B-Instruct：`triton_unk_fused_clone_npu_mrope_split_with_sizes_1` 的所有 tiling 均不可运行，未进入精度或性能阶段。
- Qwen3.8-27B-FP8：初始化超过 3600 秒；`an_mul_npu_dynamic_mx_quant_pow_rsqrt_silu_view_1` 反复出现 `empty grid (gridX=-1073741824)`，随后共享内存广播持续等待。超时后仅终止本次任务悬挂的 Worker，NPU 已释放。

## 10. 阶段结论

1. 本轮已覆盖 Dense、MoE、MLA、传统 ViT+LLM、Pooling/Embedding，以及 BF16、W8A8、W4A8-MXFP、W8A8-MXFP8、FP8 等路径，但不同路径的实际完成状态必须分别阅读。
2. DeepSeek-V2-Lite 是本轮 12 条提示词上唯一 12/12 token 和文本全一致的生成模型；Embedding 的 8 条向量均保持很高余弦相似度。
3. 其他已完成生成模型的性能总体接近 default，但 token 一致率从 0/12 到 11/12 不等，不能用性能达标替代标准精度测试。
4. 三个 W8A8 MoE 模型被相同 eager 参数类型问题阻塞；Qwen2.5-VL 和 Qwen3.8 FP8 则分别暴露 Inductor tiling 和量化融合 kernel 超时问题。
5. 当前结果不构成 Release 全量通过。显式图模式矩阵、标准精度测试集、完整五组性能负载及缺权重模型仍需补齐或明确排除。
