## 2. 已确认的结论（数据直接支持）

1. **padding 没有转化为设备端计算。** 三路径 Computing 相同（279.1/279.7/282.7），逐算子耗时一致。若 padding 被计算，D1024 的 Computing 必然更高。早期"回退来自 padding"的归因**错误**。
2. **扩大捕获在纯 prefill 上有效，且比 Inductor32 更有效**：D1024 TTFT -28%，I32 -11%。D1024 让 68 个片段进入 replay（D32 仅 3），Free -52%，Communication -42%。
3. **Inductor 的收益来自 Host 开销，不是计算。** I32 的 Computing 和 replay 次数与 D32 相同；唯一减少的算子是 Slice（7.8→3.8，-51%）；收益体现为 launch -9%、Free -20%。
4. **矩阵实验中 27B D1024 整体收益有限的原因不在 prefill 本身**：纯 prefill 变快 28%，但持续到达负载下停顿簇中位时长反而变长（111→150 ms）。混合批次的具体机制**尚未 Profile 验证**。

## 3. 实验过程中的纠错记录

- **第一轮 I32 数据无效**：采集脚本把 Inductor 编译配置写成 `None`，服务实际跑 AscendCompiler。发现依据：Profile 无 triton kernel、算子分布与 D32 完全一致、server.log 显示 `backend: AscendCompiler`。已删除并重跑，脚本加了 backend 硬校验。
- **矩阵实验（`20261123_capture_qps_matrix_01`）和对照实验（`20261123_27b_capture1024_comparison_01`）的 Inductor backend 已核查为正确**（走 `server.py --track inductor`），不受此 bug 影响。

### 四路径结论（数据直接支持）

1. **Inductor 的净效果（捕获相同）**：D32→I32 TTFT -11%（296.6→265.1），D1024→I1024 第 2 遍 TTFT **持平**（212.2 vs 212.3）。**在 27B 纯 prefill 上，捕获扩大到 1024 后，Inductor 相对 Default 没有额外 TTFT 收益。**
2. **两种优化作用于同一处**：扩大捕获（D32→D1024）省的是 Free（162→78）和 Communication（247→143）；Inductor（D32→I32）省的也是 Free（162→131）和 Communication（247→195）。它们优化的是同一个 Host/空闲开销，所以**不可叠加**：I1024 ≈ D1024。
3. **Inductor 的计算没有变快**：Computing 四路径都是 279～284 ms。Inductor 消除 Add/Sigmoid/Mul/RmsNorm（共约 5 ms）并换成 11 种 triton kernel（15.3 ms），设备端反而略多。它的全部价值在 Host 侧。
4. **两遍差异真实存在**：I1024 r1 的 TTFT 247 vs r2 212，Stage 589 vs 501。单次测量不可靠，必须多遍。D32/D1024/I32 目前只有 1 遍，结论 1 的"持平"以 I1024 r2 为准，需补 D1024 第 2 遍确认。

### 5.3 公平对照下的结论

1. **Inductor 的净收益随捕获窗口变化很大**：捕获 32 时 +10%（8B）/ +10～15%（30B）；捕获都开到 1024 后只剩 **+2%（8B）/ +3%（30B）**。两者作用于同一个 Host/空闲开销，大部分不可叠加。
2. **Inductor 从扩大捕获中获益的幅度与 Default 相当**：8B +7.5%，30B +10.4%（Inductor）；Default 为 8B +16%，30B +17～23%。Default 起点更低所以增幅更大。
3. **扩大捕获和 Inductor 可以叠加一小部分**：I1024 比 D1024 仍高 2～3%，两遍一致，是真实的小幅收益。
4. **最优配置是 Inductor + 1024**（8B QPS16 3205，30B QPS16 1823），比原始 Default32 高 18%（8B）/ 27%（30B）。
5. 两遍之间高度一致（I1024 QPS16：3205/3203；D1024 QPS16：3133/3168），结果可信。

**对之前报告的修正**：旧矩阵中"Default1024 反超 Inductor32"是因为 Inductor 没开 1024。公平对照下 Inductor 仍领先，但净优势从 +10% 缩小到 +2～3%。

| 模型 | I32/D32 | I1024/D1024 | D1024/D32 | I1024/I32 |

### 5.5 公平对照下的结论

1. **三模型一致：捕获相同时 Inductor 领先 +9～15%；都开到 1024 后收窄到 +1.4～3.3%。** 两者作用于同一处 Host/空闲开销，大部分不可叠加。
2. **27B 是三者中 Inductor 净优势最小、扩大捕获收益也最小的**：D1024/D32 只有 1.077（8B 1.165、30B 1.226），I1024/I32 为 1.000（Inductor 从扩大捕获中完全没获益）。QPS4 下扩大捕获对 27B 反而是回退（0.953），QPS32 下 I1024 略低于 D1024（0.974）。
3. **27B 两遍波动比 8B/30B 大**：I1024 QPS16 两遍 1147/1204 相差 5%，D1024 QPS4 两遍 879/919 相差 4.5%。27B 的 1.014 这个数应视为"约持平"，不能当成精确的 +1.4%。
4. **27B 的 TP2 是最可能的差异来源**（未验证）：TP2 下每个 rank 都要独立捕获 12 个尺寸的 PIECEWISE 图，混合批次 replay 时的两 rank 同步开销可能更高。这需要 TP2 的单卡 Profile 对比才能确认。
