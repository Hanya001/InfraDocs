# Inductor 性能优化实验与编译期定点优化分析

日期：2026-11-26。环境：A5-28，Ascend950DT，torch 2.13、vLLM/vllm-ascend 0.33。

本文记录从性能问题定位到优化实验的完整过程，包括有效结果、失败方案以及后续应采用的编译期定点实现方式。所有后台实验任务均已停止。

## 1. 问题背景

此前 14 个 TP1 模型的捕获 1024 性能矩阵显示：

- 84 个“模型 × 负载”组合中，63 个吞吐加速比中位数处于 0.98～1.02；
- QPS1/QPS4 吞吐受到请求到达率限制，不能单独用于判断 Inductor 是否有效；
- 32K 输入有 7/14 个模型吞吐下降超过 2%；
- default 与 Inductor 都使用 O2、`FULL_AND_PIECEWISE` 和 1024 捕获，双方一部分 Host 收益重叠。

因此需要分别处理三类问题：

1. VL 长输入中的无效 QKV 复制；
2. 27B 长输入中的低效 Triton Sigmoid+Mul 和状态清零；
3. 30B MoE 回退抵消 Norm/Slice 融合收益。

## 2. 实验方法与隔离要求

实验使用 A5-28 独立容器，并遵循：

- 原始共享工作区不修改；
- 原始源码与修改源码分别放在独立副本；
- 独立 vLLM、Inductor、Triton 缓存；
- 相同 token ID、输入形状、请求数、输出长度和 NPU；
- TP1、1024 捕获配置；
- Profile 用于解释设备时间，非 Profile 请求用于确认正式收益。

主要结果归档：

- `server-results/benchmark-diagnosis/20261126_inductor_optimization_a5_28/`
- `server-scripts/benchmark-diagnosis/20261126_inductor_optimization/`

## 3. 原始问题定位

### 3.1 VL：完整 QKV 读改写包含无效的 V 流量

每层 QKV 共 4608 个通道：

- Q：前 3584 个；
- K：接下来 512 个；
- V：最后 512 个。

MRoPE 只更新 Q/K，但原 Inductor 生成的 `copy_split_with_sizes` kernel 会读取并写回整个 QKV，连不变化的 V 也包括在内。

原始 Profile：

- `copy_split_with_sizes_3` 约 2.788 秒；
- `copy_split_with_sizes_4` 约 0.103 秒；
- 长 prefill Computing：default 约 14.87 秒，原 Inductor 约 17.52 秒。

主要问题不是 MatMul 或 Attention 变慢，而是复制成本抵消了其他优化。

### 3.2 27B：Sigmoid+Mul 和 Zeros 抵消融合收益

27B 长 prefill 的主要新增开销：

| 生成 kernel | 累计时间 |
|---|---:|
| `mul...sigmoid_view` | 约 1.201 秒 |
| `zeros_4` | 约 0.591 秒 |
| `unsafe_view_clone_view` | 约 1.377 秒，本次未处理 |
| `index_3` | 约 0.070 秒，本次未处理 |

名称包含 `dynamic_quant` 的 kernel 实际只执行两次读取、Sigmoid、乘法和写回，动态量化仍由后续原生 `npu_dynamic_quant` 执行，因此不能把问题归因于量化。

Zeros 创建的 GDN 状态会返回给后续执行，不能直接删除，只能优化初始化方式。

### 3.3 30B：MoE 回退抵消 Norm/Slice 收益

30B 固定 decode Profile 显示：

- RmsNorm 和 Slice 融合确实减少 Computing；
- GroupedMatmulSwigluQuantV2 和 GroupedMatmul 在相同形状、相同调用次数下仍慢约 4%；
- 这部分回退抵消了约一半本可获得的计算收益。

当时假设 default 的防御性 Clone 可能提供更合适的地址对齐或布局，需要通过强制 Clone 实验验证。

## 4. 有效优化结果

### 4.1 VL：直接返回新 Q/K

Qwen2.5-VL 的调用方使用 `q, k = rotary_emb(...)` 的返回值，因此多模态 MRoPE 可以直接返回新生成的 Q/K，不需要写回原 QKV。

最终实现策略：

- 多模态、二维 position 的 Inductor 路径直接返回新 Q/K；
- DFlash/DSpark 依赖原地写的路径保留原复制行为；
- 不再使用 mutation custom op。

效果：

- 完整 QKV 复制 kernel 消失；
- prefill Computing 从 17.52 秒降至 14.56 秒，略低于 default 的 14.87 秒；
- 不再出现第一版 mutation custom op 导致的非法地址错误。

两轮非 Profile 平均结果：

| 指标 | 原 Inductor | 修改后 | 改善 |
|---|---:|---:|---:|
| 批次总时间 | 29.0016 s | 25.7224 s | -11.31% |
| 平均 TTFT | 9.9287 s | 8.2590 s | -16.82% |

逐轮数据：

| 轮次 | 原批次时间 | 原 TTFT | 修改后批次时间 | 修改后 TTFT |
|---|---:|---:|---:|---:|
| 1 | 29.0003 s | 9.9304 s | 25.7204 s | 8.2585 s |
| 2 | 29.0028 s | 9.9269 s | 25.7244 s | 8.2595 s |

对应实验补丁：`mrope_fresh.patch`。

### 4.2 27B：原生 Sigmoid+Mul 和原生清零

实验新增两个 custom op：

- `sigmoid_mul`：原生 `x * torch.sigmoid(gate)`；
- `gdn_zeros`：原生 `torch.zeros`。

`gdn_zeros` 使用参考 tensor 决定 dtype 和设备，避免无 tensor 参数时无法按 NPU 分派。

小函数结果：

| 算子 | 原 Triton | 原生实现 |
|---|---:|---:|
| Sigmoid+Mul | 2.297 ms | 0.159 ms |
| Zeros | 0.383 ms | 0.025 ms |

模型 Profile 中，两类目标 Triton kernel 消失，prefill Stage 从 30.76 秒降至 29.11 秒。

两轮非 Profile 平均结果：

| 指标 | 原 Inductor | 修改后 | 改善 |
|---|---:|---:|---:|
| 批次总时间 | 52.8089 s | 51.1756 s | -3.09% |
| 平均 TTFT | 17.8977 s | 16.9226 s | -5.45% |

逐轮数据：

| 轮次 | 原批次时间 | 原 TTFT | 修改后批次时间 | 修改后 TTFT |
|---|---:|---:|---:|---:|
| 1 | 52.7956 s | 17.8908 s | 51.1591 s | 16.9187 s |
| 2 | 52.8222 s | 17.9047 s | 51.1922 s | 16.9265 s |

原始组与修改组的 `acc_track.jsonl`、`acc_repeat2.jsonl` 完全相同，SHA-256 均为：

`1da69372af1ca4af0b193a4cee179942d785b76841cbea9d8544f2e1961f37c1`

因此修改没有引入额外数值差异。需要同时保留另一个事实：原始 Inductor 和修改后在现有规则下均为 token 0/8、logprob 容差未通过，精度问题需要单独分析，不能宣称本次性能修改解决了精度问题。

对应实验补丁：`native_ops.patch`、`sigmoid_mul.patch`、`gdn_zeros.patch`。

## 5. 否定性结果：30B 强制 Clone 无效

强制在 MoE 前执行 `hidden_states.clone()` 后：

- 两类 MoE kernel 没有恢复到 default 水平，反而更慢；
- decode Stage 从 646.8 ms 增至 665.2 ms；
- 整体请求时间约 34.154 s → 34.126 s，基本没有变化。

因此，“缺少 Clone 导致 MoE 回退”的假设不成立，不再沿强制 Clone 或简单的地址对齐解释投入。

`moe_clone.patch` 仅作为否定性实验记录保留。

## 6. 已暴露的实现问题

前面的有效数据证明了优化方向，但初版实现仍然较粗糙，不能直接作为最终代码。

### 6.1 模型 forward 修改范围过大

初版修改落在模型 forward 中。虽然部分分支只在 Inductor 下生效，但会影响代码结构、其他后端审查和后续维护。更合适的位置是 vllm-ascend 的 Inductor 编译链。

### 6.2 `_foreach_copy_` 不是有效替代

最小用例中：

- 当前融合复制约 0.854 ms；
- `_foreach_copy_` 约 0.932 ms。

因此不采用 `_foreach_copy_` 替代 MRoPE 复制。

### 6.3 post-grad pass 的初次实现存在两个具体问题

第一，`torch.ops.vllm.sigmoid_mul` 是算子包，FX `call_function` 需要具体 overload，必须写 `.default`。该问题已在实验中修正。

第二，初版 pass 将 `sigmoid_mul(x, sigmoid(gate))` 传入新算子，而新算子内部还会计算一次 Sigmoid。正确替换应是：

```text
原图：sigmoid(gate) → mul(x, sigmoid(gate))
替换：sigmoid_mul(x, gate)
```

如果错误传入 `sigmoid(gate)`，不仅多保留了一个 Sigmoid kernel，还会改变数值语义。该版本不能作为结果使用。

此外，pass 后仍出现 `zeros_4`，说明清零节点没有被完整处理，需要检查替换后的实际图和生成代码，不能只看 pass 命中日志。

### 6.4 全局算子 fallback 范围过大

实验曾设置：

```bash
NPU_INDUCTOR_FALLBACK_LIST=aten.sigmoid,aten.mul,aten.zeros
```

其中 `aten.mul` 会影响模型中所有乘法，直接破坏其他融合机会。这组任务已停止，没有采用其结果。

正确做法不是全局禁用某个 ATen 算子，而是只处理目标子图或目标融合组。

## 7. 后续正确的实现方式

### 7.1 优先：精确子图替换

在 vllm-ascend 的 post-grad FX pass 中，只匹配完整目标链：

```text
sigmoid(gate) → mul(x, sigmoid(gate))
```

然后替换为一个 extern/native `sigmoid_mul(x, gate)`：

- 原始 gate 作为参数，不能传 Sigmoid 后的结果；
- 原 Sigmoid 节点应因无用户而被删除；
- 其他 `mul` 和其他融合完全不动；
- default 和模型 forward 不改。

Zeros 只处理 GDN 对应的状态分配，需要同时检查：

- FX 节点确实被替换；
- 生成代码不再包含 `zeros_4`；
- 返回缓冲区的 shape、stride、dtype 和后续状态更新一致。

MRoPE 只匹配由 `npu_mrope` 结果驱动的 `copy_`，并验证精确 stride/别名约束，不能全局禁用 `aten.copy_`。

### 7.2 备选：只禁止目标融合组

如果希望保留原生 ATen 节点，可在 Inductor scheduler 的融合判断中增加精确 guard：

- 只拒绝 Sigmoid+Mul 这一条融合组；
- 或只拒绝 MRoPE 对应的完整 QKV 合并复制；
- 其他相同 ATen 算子仍可正常生成 Triton 和参与融合。

该方式实现复杂度更高，但比全局 fallback 更符合“只跳过某个融合”的目标。

### 7.3 不建议继续采用

- 全局 `aten.mul` fallback；
- 全局 `aten.copy_` fallback；
- `_foreach_copy_` 替代；
- 直接强制 MoE Clone；
- 只看 pass 命中数、不检查最终生成代码的实现。

## 8. 后续验证要求

每项编译期修改至少需要：

1. **图级检查**：打印替换后的 FX 图，确认目标节点完整替换且无重复 Sigmoid。
2. **生成代码检查**：确认目标 Triton kernel 消失，其他融合仍保留。
3. **小函数数值检查**：覆盖连续和非连续布局，检查 gate 未被重复计算。
4. **固定输入精度**：比较原始与修改后的 token/logprob，而不只比较文本。
5. **相同形状 Profile**：确认目标 kernel 的时间下降且没有转移到其他节点。
6. **非 Profile 复测**：至少两轮，保持相同输入、并发、缓存和捕获配置。
7. **跨形状回归**：同时覆盖 ShareGPT 中短输入和 8K/32K 长输入。
8. **作用域检查**：确认 default、模型 forward 和其他 ATen 算子的行为未改变。

## 9. 当前结论

- VL 的 Q/K 返回优化和 27B 的原生 Sigmoid+Mul/清零，已经在独立实验中显示出可重复的性能收益。
- 27B 的生成结果与原始实现完全一致，未引入额外数值差异。
- 30B 强制 Clone 已被证明无效。
- 后续工作重点是把这些优化迁移到 vllm-ascend 的 Inductor 编译链，以精确子图替换或精确融合 guard 实现，避免全局算子 fallback 和粗糙的模型 forward 修改。
