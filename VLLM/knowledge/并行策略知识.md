# 切分对象

你问过：

- “TP 和 EP 怎么同时跑在同一张卡上？”
- “TP 能不能减少 KV Cache？”
- “TP 和 DCP 相互通信传什么？”

这些问题背后默认了一个模型：

```
一张卡/一个实例
要么采用 TP，要么采用 EP，要么采用 DCP
```

但真实情况是：

```
同一批卡
├── Attention 权重：按 TP 切
├── MoE 专家：按 EP 切
├── MLA KV Cache：普通 TP 下复制，DCP 下按 token 切
├── 不同层：可以按 PP 切
├── 不同请求：可以按 DP 分
└── 激活：在各阶段通过不同集合通信合并
```

所以不是“TP 和 DCP 两组机器相互通信”，而是：

> **同一个 rank 同时属于多个逻辑通信组，在不同阶段参与不同集合通信。**

## 一个通用的五问框架

以后看到任何并行配置，不要先问“它用了哪种并行”，而是对每类数据分别问：

```
1. 切的是什么对象？
2. 沿哪个维度切？
3. 哪些东西仍然复制？
4. 计算时谁需要谁的数据？
5. 最后通过什么通信恢复原数学语义？
```

对应关系可以概括为：

| 并行方式 | 主要切分对象         | 典型切分维度       | 典型通信                      |
| :------- | :------------------- | :----------------- | :---------------------------- |
| DP       | 请求、Batch          | 请求维度           | 普通推理 DP 通常无需逐步同步  |
| PP       | 模型层               | Layer 维度         | 相邻阶段点对点传激活          |
| TP       | 矩阵、Attention Head | Hidden/Head 维度   | AllReduce、ReduceScatter      |
| EP       | MoE 专家             | Expert 维度        | All-to-All 路由 token         |
| CP/DCP   | 序列、KV Cache       | Token/Context 维度 | 传 Q/KV 或局部 Attention 结果 |

最关键的一条是：

并行方式=数据布局+计算映射+通信恢复

只知道“切了”还不够，还必须知道**切了什么、谁被复制、怎么合并**。

## 第二个相关盲区：权重、KV、激活是三套不同布局

“Attention 使用 TP”并不自动意味着 Attention 相关的所有数据都被 TP 切分。

| 数据             | 生命周期       | 普通 TP 下的典型情况             |
| :--------------- | :------------- | :------------------------------- |
| Attention 权重   | 静态           | 按 Head/Hidden 切分              |
| MHA/GQA KV Cache | 随请求动态增长 | KV Head 足够时可以切分           |
| MLA latent KV    | 随请求动态增长 | 所有 Head 共用，通常复制         |
| 当前激活         | 临时存在       | 各 rank 计算部分结果，再通信合并 |

MLA 之所以成为一个很好的例子，正因为它说明了：

> **权重被切分，不代表 KV 也被切分；计算被并行，不代表所有输入数据都能并行拥有。**

每个 TP rank 的 Head 上投影权重确实不同，但它们都依赖完整的共享 latent，所以 latent KV 只能复制。这里不是 TP 失效，而是**数据依赖决定了布局**。

## 再从“一张卡的一天”理解并行

与其把卡想成“TP 卡”或“EP 卡”，不如看它在一次前向计算中的时间线：

```
时刻 1：作为 TP rank，计算本地 Attention Head
时刻 2：作为 DCP rank，读取本地 KV 分片并交换 Q/局部结果
时刻 3：作为 TP rank，参与输出激活的 AllReduce
时刻 4：作为 EP rank，发送和接收路由 token
时刻 5：作为 EP rank，计算本地专家
时刻 6：作为 PP rank，把激活发送给下一个流水线阶段
```

物理卡没有换，变的是它当前参与的**逻辑计算和通信组**。

所以“EP 没选中专家的卡是否不用跑”也不能只看整张卡，而要精确到：

- 它有没有本地 Expert GEMM？
- 它是否仍需参加 EP All-to-All？
- 它是否还有 Attention、共享专家或后续层计算？
- 它是否必须等待全局同步？

## 最终心智模型

不要从“这个模型是 TP8、EP32、DCP8”开始理解，而从下面这句话开始：

> **集群里只有一组 rank；每种并行只是给这些 rank 定义了一种特定的数据分布和通信关系。**

然后对每层依次追踪四样东西：

```
权重在哪里？
KV Cache 在哪里？
当前激活在哪里？
为了完成数学计算，还需要从哪里拿什么数据？
```

只要这四点弄清楚，TP、EP、DCP、PP 的组合、通信内容、显存占用和空泡位置，基本都能自己推导出来。
